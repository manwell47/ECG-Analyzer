# Committed ONNX Model Artifacts

Committed, deterministic ONNX artifacts for the ECG Signal Processing & AI
Analysis Laboratory. Like the golden fixtures in
[`../reference/`](../reference/README.md), these small files are **part of the
repository** and never silently drift. Unlike the JSON golden files (which are
regenerated in memory from TypeScript), these are generated by a Python `onnx`
script, so their anti-drift guard is a recorded byte length + SHA-256 asserted
by a TypeScript loader test plus a real ONNX Runtime session test.

> **Scientific status — read first.** Every model under this directory is a
> *development seam-validation probe*, not a scientific or clinical model. Its
> purpose is to exercise the inference plumbing end-to-end (Signal → ModelInput
> → real ONNX session → interpret) with a tiny, fully deterministic graph whose
> outputs a test can reproduce exactly. Never present any of these artifacts as
> a beat classifier, diagnostic aid or research result.

## How the artifacts are produced

Run from the repository root:

```text
python data/fixtures/models/generate-probe-model.py
```

The script uses no randomness and pins every producer field and the opset, so
re-running it regenerates **byte-identical** `.onnx` and `.metadata.json` files.
It runs `onnx.shape_inference` and `onnx.checker.check_model(full_check=True)`
before writing, then prints the byte length and SHA-256.

Current committed integrity record (asserted by
[`probeModel.test.ts`](../../src/ml/testing/__tests__/probeModel.test.ts)):

```text
size   543 bytes
sha256 deec0c5b9d42c243515d7b23160aff91f883c8cfeb5cb9f06d47ffcdd3987052
```

If you regenerate with a different `onnx` version and the bytes change, update
the recorded constants in [`src/ml/testing/probeModel.ts`](../../src/ml/testing/probeModel.ts)
and this file together — the loader test will fail loudly until they match
(the binary must not change silently).

## Model semantics (the oracle)

For a single 360-sample float32 window `x` at 360 Hz:

- `window_sum = Σ x`
- `logits = [+window_sum, −window_sum]`

Interpreted with the declared `softmax` activation this is a probability over
two classes whose argmax is the **sign of the window mean**:

| window sum | argmax class |
| ---------- | ------------ |
| `> 0`      | `positive-mean`     (index 0) |
| `< 0`      | `nonpositive-mean`  (index 1) |
| `= 0`      | exact tie → deterministic tie-break to index 0 |

Because the op is a plain sum of a float32 window, integration tests feed exact
windows (e.g. a constant 0.5 mV → sum 180.0, or constant −0.5 mV → sum −180.0)
whose logits are exactly representable, so the real-session assertions are exact
and reproducible.

## Provenance / reproducibility gate

The numerical output of this graph has **not** been fabricated or hand-tuned to
pass: the test oracle *is* the closed-form sign-of-mean rule above, and the
runtime proof lives in the Phase-7 item #4 integration test
(`src/ml/onnx/__tests__/*.test.ts`), which loads these exact bytes into an ONNX
Runtime session and compares against the rule.
